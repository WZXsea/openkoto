# OpenKoto Desktop 0.12.5 Assistant 任务可靠性热修复
## 发布定位
0.12.5 修复 Assistant 任务已写入 Backend 后长期停留在 `queued` 或 `running`、思维导图面板错过事件后不再更新，以及内置 Assistant 动作固定停在 50% 的问题。
## 根因与修复
1. 移除 Worker 启动热路径中嵌套的 Tauri async runtime `block_on`，避免任务在 checkpoint 和 stdout listener 建立前中断。
2. Worker 状态事件改用完整 task payload 指纹作为幂等键，允许同一 `updated_at` 下合法的 `running → succeeded` 连续更新。
3. Worker stdout 结束时自动终结仍有 checkpoint 的非终态任务。
4. 应用启动时扫描 Backend 中早于本次启动且缺少 checkpoint 的 `queued/running` 孤立任务，将其转为可重试失败。
5. 思维导图面板重新挂载时恢复当前素材的活动任务，并对活动 task ID 轮询，避免瞬时事件丢失造成界面冻结。
6. Worker 尚未发送 `worker.ready` 时健康状态显示为 `starting`，不再误报为 `stopped`。
## 验收证据
1. Backend 全量测试通过；新增同时间戳 `running → succeeded` 回归覆盖。
2. Agent worker 37 项测试通过。
3. Desktop Rust 全量测试通过；新增孤立任务恢复和启动中健康状态覆盖。
4. Frontend 64 个测试文件、283 项测试通过；新增任务轮询恢复与面板重挂恢复覆盖。
5. 生产构建通过；Playwright 6 项通过、2 项按环境条件跳过。
6. PR-12 Assistant 可观察性静态守卫通过，明确禁止 `ensure_started` 内再次使用 `block_on`。
## 运行行为
1. 升级后首次启动会将旧的无 checkpoint 孤立任务标记为失败，并保留原任务和时间线。
2. 用户可在 Assistant 任务中心对该失败任务执行“重试”；重试创建新 attempt，不覆盖旧任务。
3. 本热修复不新增外部软件连接或写入能力。
