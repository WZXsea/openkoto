# OpenKoto Desktop 0.12.6 Assistant 重试与进度反馈修复
## 问题
0.12.4 中，Assistant 重试任务会在本地 Worker 确认前被写为 `running/retry_dispatch`。Worker 启动路径随后可能在 Tauri 异步命令内发生嵌套运行时阻塞，导致 Backend 已记录运行状态，但没有 Worker 进程、checkpoint、`worker.ready` 或 `task.started` 事件。
## 修复
1. 保留 0.12.5 已完成的 Worker 启动、异常退出、孤儿任务恢复和 Backend 状态幂等修复。
2. 重试分发阶段保持 `queued/retry_dispatch`；只有 Worker 发出 `task.started` 后才进入 `running` 并设置开始时间。
3. 应用重启后，无 checkpoint 的旧排队或运行任务会收敛为可重试的失败状态。
4. `queued`、`running` 状态增加旋转指示和活动进度条。
5. 重试、取消提交期间增加旋转反馈。
6. 动效遵守 `prefers-reduced-motion`，进度条保留 ARIA 数值和状态播报。
## 现场诊断
2026 年 7 月 19 日现场检查显示，实际运行的 Desktop 与 Backend 均为 0.12.4。卡住的重试任务只有 `created → queued` 和客户端写入的 `queued → running/retry_dispatch`，`worker_session_id` 为空，也没有对应的本地 checkpoint。
## 升级行为
退出旧版并用 0.12.6 替换 `/Applications/OpenKoto Desktop.app`。首次启动时，应用会更新 Backend sidecar，并将此前遗留的活动任务恢复为失败状态；随后可从该失败任务重新重试。
