# OpenKoto Desktop 0.12.7 Agent Provider 运行时修复
## 发布范围
本次为 `WZXsea/openkoto` 的 macOS Apple Silicon 预发布版本。应用使用本地 ad-hoc 签名，未附带 Apple notarization ticket；首次打开时可能需要在 macOS“隐私与安全性”中确认。
## 问题
0.12.6 已能正常启动 Agent Worker，但 Worker 使用 `@opencode-ai/sdk` 创建本地运行时。该 SDK 会固定执行系统命令 `opencode serve`，安装包没有携带 OpenCode CLI，因此任务在 35% 分析阶段失败：
```text
Agent runtime execution failed: spawn opencode ENOENT
```
## 现场证据
1. Desktop、Backend 和 Worker 均已正常启动。
2. 失败任务存在 `worker_session_id`，说明任务已经进入本地 Worker。
3. 任务进度到达 `analyzing / 35%` 后失败。
4. 安装包中包含 `@opencode-ai/sdk`，但系统和应用资源中均不存在 `opencode` 可执行文件。
5. 当前模型为 `openai-compatible / deepseek-v4-flash`，配置的 Base URL 为 `https://opencode.ai/zen/go/v1`。
## 修复
1. OpenAI-compatible Provider 改由 Bundled Node 直接调用 `{baseUrl}/chat/completions`。
2. 模型请求使用原始模型 ID，并传递 system/user messages。
3. 思维导图输入直接携带文章快照与输出 Schema，不再要求外部 Agent 读取临时工作区。
4. 请求支持用户取消和 120 秒独立超时。
5. Provider 错误限制长度并脱敏 API Key 与 Bearer Token。
6. Worker 运行时标识更新为 `direct-provider`。
7. Google、Anthropic 在内置直连尚未实现时明确失败，不再回落到缺失的外部 CLI。
## 验证
1. Agent Worker 41 项测试通过。
2. Worker 类型检查与编译通过。
3. 编译后的 Worker 对本地假 `/chat/completions` 完成 `task.started → progress → task.result`，错误事件为 0。
4. 当前真实 DeepSeek V4 Flash endpoint 已通过极小合成 JSON 请求验证，未发送现有文章内容。
5. Desktop Rust 107 项和 Agent Worker Rust 集成测试 27 项通过。
6. App 深度签名结构、DMG 完整性和挂载结构检查通过。
7. 安装包内 Worker 启动握手返回 `runtime=direct-provider`。
8. 安装 0.12.7 后，从应用内重试原失败任务：任务在约 111 秒内由排队、运行、分析、校验、保存推进至完成，进度为 100%，并生成 1 个 `mind_map` 产物。
